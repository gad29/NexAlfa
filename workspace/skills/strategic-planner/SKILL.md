# Strategic Planner

## Purpose
Turn vague goals into clear plans, roadmaps, milestones, risks, priorities, and execution checklists.

## Use When
- Planning a product, business, automation, campaign, or technical project
- Breaking a big goal into phases
- Prioritizing tasks or features
- Creating roadmaps, sprint plans, launch plans, or risk registers
- Deciding what to do next

## Safety Model
This is a planning framework skill only. It does not alter calendars, send messages, or execute plans unless separately instructed.

## Planning Workflow
1. **Define outcome**: what finished means, in measurable terms.
2. **Identify constraints**: time, budget, tools, people, dependencies.
3. **Map stakeholders/users**: who benefits, approves, builds, maintains.
4. **Break into phases**:
   - Discovery
   - Design
   - Build
   - Test
   - Launch
   - Improve
5. **Prioritize**:
   - Impact
   - Effort
   - Risk
   - Urgency
   - Dependencies
6. **Create milestones**: Now / Next / Later or weekly phases.
7. **Risk plan**: assumptions, blockers, mitigations, fallback.
8. **Execution rhythm**: review cadence, owner, next actions.

## Roadmap Rules
- Roadmaps should communicate direction, not fake certainty
- Use Now/Next/Later when exact dates are premature
- Link strategy to delivery tasks
- Review quarterly for larger initiatives, weekly for active execution
- Avoid overloading roadmaps with low-level requirements

## Prioritization Methods
### ICE
Impact × Confidence × Ease. Good for quick feature prioritization.

### RICE
Reach × Impact × Confidence / Effort. Better when audience size matters.

### MoSCoW
Must, Should, Could, Won't. Good for scope control.

### Risk-first
Do the riskiest unknowns early when failure would be expensive.

## Planning Output Format
1. Goal statement
2. Assumptions
3. Milestones/phases
4. Task breakdown
5. Priorities
6. Dependencies
7. Risks and mitigations
8. Next 3 actions
9. Definition of done
